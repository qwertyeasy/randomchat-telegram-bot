# Roadmap: Рекомендательная система для анонимного чата

## Контекст

Telegram-бот для анонимного общения (аналог чат-рулетки).  
Цель: превратить случайный матчинг в интеллектуальную рекомендательную систему,  
которая подбирает максимально подходящего собеседника на основе психологического профиля.

**Ключевой принцип:** тексты сообщений **никогда не хранятся** — только агрегированный психологический профиль (вектор личности). Privacy by design.

**Мультиклиентность** — в план не включена, реализуется после полной настройки системы в рамках Telegram.

---

## Фаза 0 — Текущее состояние (точка отсчёта)

- Одна глобальная очередь, случайный пейринг
- Фильтр по полу (единственный hard filter)
- Анонимный чат, выход по команде
- Нет хранения истории, нет профилей

---

## Фаза 1 — Архитектурный рефакторинг (~2–3 нед)

**Цель:** отделить бота (Telegram layer) от бизнес-логики, заложить фундамент.

### Что делаем
- Структурировать код: `bot/` → handlers, `services/`, `db/`, `core/`
- Ввести PostgreSQL — пользователи и сессии
- Redis — очереди матчинга (заменяет in-memory)
- Docker Compose для локальной разработки

### Базовая схема БД
```sql
users(id, tg_id, gender, created_at, msg_count, is_active)
sessions(id, user_a, user_b, started_at, ended_at, msg_count_a, msg_count_b)
```
Тексты сообщений **не хранятся**.

### Стек
`aiogram 3` · `FastAPI` · `PostgreSQL` · `SQLAlchemy 2` · `Alembic` · `Redis` · `Docker Compose`

### Результат
Тот же бот, но на нормальной архитектуре — каждая следующая фаза добавляется без переписывания.

## Фаза 2 — Профиль пользователя + онбординг (~1–2 нед)

**Цель:** у каждого пользователя есть профиль с момента первого запуска.

### Что делаем
- Таблица `user_profiles`: `personality_vector FLOAT[12]`, `interest_tags TEXT[]`, `geo POINT`, `mbti_scores FLOAT[4]`
- Онбординг при первом запуске: 5–6 inline-вопросов (интроверт/экстраверт, темп, интересы, настроение)
- На основе ответов инициализируем вектор → решает проблему холодного старта
- Запрос геолокации (опционально, через Telegram location sharing)

### Вектор личности (12 измерений)
| idx | Измерение | Диапазон |
|-----|-----------|----------|
| 0 | energy | замкнутость ↔ открытость |
| 1 | thinking | эмоциональность ↔ рациональность |
| 2 | tone | негативность ↔ позитивность |
| 3 | depth | поверхностность ↔ глубина тем |
| 4 | humor | серьёзность ↔ юмор |
| 5–8 | emotions | joy, sadness, anger, fear |
| 9 | tempo | темп общения (короткие/длинные сообщения) |
| 10 | curiosity | задаёт вопросы / не задаёт |
| 11 | expressiveness | богатство лексики |

### Результат
Профиль есть у всех, инициализирован онбордингом. Тексты не хранятся.

## Фаза 3 — NLP Pipeline — обновление профиля (~3–4 нед)

**Цель:** профиль автоматически калибруется по речи пользователя.

### Принцип (privacy-first)
```
каждое сообщение → NLP → delta вектора → применяем к профилю → сообщение не сохраняем
```

### NLP задачи на сообщение
- **Sentiment:** positive/negative/neutral (rubert-tiny2 или DeepPavlov)
- **Emotion detection:** joy/sadness/anger/fear/surprise (multilingual модель)
- **Длина и структура:** tempo, expressiveness
- **Вопросительные конструкции:** curiosity
- **Topic detection:** interest_tags (KeyBERT или zero-shot classification)

### Decay weight (затухание при обновлении)
```python
update_weight = 1 / sqrt(msg_count + 1)
new_vector[i] = old_vector[i] + update_weight * delta[i]
```
Первые 10 сообщений дают сильный сдвиг, после 100 — незначительный.

### Оптимизация
- NLP запускается асинхронно, не блокирует чат
- Батчинг: обрабатываем раз в N секунд, не каждое сообщение отдельно
- Сообщения < 5 символов — пропускаем

### Стек
`transformers` · `DeepPavlov` · `sentence-transformers` · `KeyBERT` · `asyncio batching`

### Результат
Профиль калибруется в процессе общения. Никакого текста не хранится.

## Фаза 4 — Умный матчинг v1 (~2 нед)

**Цель:** заменить случайную очередь на similarity-based matching.

### Что делаем
- `pgvector`: personality_vector как `vector(12)` с HNSW индексом
- Score: `cosine_similarity(a.vector, b.vector) * geo_score(a, b)`
- Geo score: `exp(-distance_km / R)`, R ≈ 100 km (настраивается)
- Hard filters: пол, язык — применяем до similarity

### Стратегия при малой очереди
- < 10 человек → fallback к random (как сейчас)
- ≥ 10 → top-3 по score, случайно выбираем из них (снижаем детерминизм)

### Стек
`pgvector` · `PostgreSQL HNSW` · `PostGIS`

### Результат
Матчинг работает на реальных профилях, есть гео-приоритет. Уже лучше рандома.

## Фаза 5 — Объяснение мэтча (~1 нед)

**Цель:** пользователи видят "почему" алгоритм свёл именно их.

### Что показываем
- % совместимости = cosine_similarity * 100 (нормализованный)
- MBTI: маппинг 4 пар измерений вектора → E/I, S/N, T/F, J/P
- 2–3 строки: "Вы оба любите глубокие темы и юмор"
- Общие теги интересов

### Реализация
- Claude Haiku / GPT-4o-mini: промпт с обезличенными параметрами профилей
- Стоимость: ~$0.001 на пару
- Кешируем на сессию
- Показываем inline-сообщением в начале чата (пользователь может скрыть)

### Результат
Доверие к системе растёт, снижается отток при неудачном мэтче.

## Фаза 6 — Feedback Loop + обучающаяся матрица (~3–4 нед)

**Цель:** система обучается на результатах реальных сессий.

### Сигналы (без текстов)
| Сигнал | Тип |
|--------|-----|
| session_msg_count | позитивный, количественный |
| session_duration | позитивный, количественный |
| contact_shared | сильный позитивный, бинарный |
| early_exit (< N сообщений) | негативный, бинарный |

### Success score
```python
score = w1*log(msg_count+1) + w2*duration_min + w3*contact_bonus - w4*early_exit_penalty
# нормализуем в [0, 1]
```

### Матрица совместимости
- Храним: для каждой пары (vector_bucket_a × vector_bucket_b) → накопленный score
- Старт: identity (равные веса)
- Обновление: EMA (exponential moving average)
- Продвинутая версия (при наличии данных): LightFM / implicit ALS

### Обновление личного профиля
- Успешная сессия → слегка смещаем вектор пользователя в сторону вектора партнёра
- Неуспешная → без изменений (не штрафуем)

### Результат
Система обучается на данных, матрица становится умнее с ростом базы.

## Фаза 7 — Качество, мониторинг, итерации (ongoing)

### Ключевые метрики
| Метрика | Что измеряет |
|---------|--------------|
| Median session length (msg) | качество мэтчей |
| Contact share rate | % успешных пар |
| Early exit rate | % провальных мэтчей |
| Return rate | удержание пользователей |
| Queue wait time | нагрузка на очередь |

### A/B тестирование
- Группа A vs B: разные веса geo / similarity
- Тест: влияют ли объяснения мэтча на длину сессии

### Возможные улучшения NLP
- Toxicity detection — автобан за агрессию
- Language detection — языковые группы
- Spam detection — защита от ботов
- Fine-tuning на агрегированных данных

## Приоритет при ограниченном времени

Если нужно запустить быстро, пропустить NLP на первое время:

```
Фаза 1 → Фаза 2 → Фаза 4 (матчинг по онбордингу) → Фаза 3 (NLP поверх) → Фаза 5 → Фаза 6
```
